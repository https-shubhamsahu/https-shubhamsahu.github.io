NO SUS

Private sharing, with an expiry date.

An Android and web app for sharing documents, sending burn notes, and opening selected Drive files on a borrowed computer.

Live website · Android 1.1.8 + web

What I built

Sharing a file often means losing track of access. I wanted the sender to keep useful controls after sending it.

  • Built a Flutter client and Supabase backend for document sharing, viewer-entered email watermarks, view limits, expiry, and access logs.
  • Added browser-encrypted burn notes and files, plus a phone-approved flow for opening selected Drive files on another computer.
  • Direct-link keys stay in the URL fragment; short pairing codes temporarily hold the key server-side. Watermarks provide an attribution clue, not verified identity.
  • Released Android 1.1.8 after restarting version numbering. The release documents web fallbacks for Android links, accessible link-page controls, camera-photo recovery and crash-report controls.
  • The current release series adds username.nosus.foo addresses, phone-approved sessions on another screen and optional one-use, ten-minute sharing codes. For codes the server temporarily holds the key; direct links remain the default. The server migration requires signing in again, and old links, groups and accounts do not carry over.

Tools: Flutter, Dart, Supabase, Browser cryptography.
